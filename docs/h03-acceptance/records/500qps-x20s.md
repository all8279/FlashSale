# 500 QPS × 20 秒

## 场景

- 活动：`activity_id=6`，商品 `product_id=6`，初始库存 300，`purchase_limit_per_user=2`
- 用户池：2,000 个 CUSTOMER（`load/h03/tokens.txt`）
- 发压方式：`constant-arrival-rate`，500 req/s，持续 20 秒，目标 10,000 次
- 执行时间：2026-11-02，本机 Docker 环境（16 GB 内存，25 个容器）
- 原始结果：`docs/h03-acceptance/evidence/k6/500qps-x20s-summary-k6.json`

## 结果

| 指标 | 数值 |
|---|---:|
| 实际请求 | 10,001 |
| 实际速率 | 499.9 req/s |
| dropped iterations | 0 |
| P50 | 4.0 ms |
| P95 | 81.0 ms |
| max | 693.7 ms |
| 成交订单 | 300（等于活动库存） |
| 活动 Redis 库存 | 0 |

- 未发现超卖，未发现重复有效订单。
- `verify.sql` 七项对账全部 0 违规。

## 结论边界

- 数据库侧库存投影是异步追平的。压力结束后投影仍需时间追平，本次记录执行时
  `activity_inventory_checkpoint=256/300`，因此该场景只证明售罄过程无超卖、无重复有效订单，
  不作为“数据库与 Redis 实时强一致”的结论。
- 本场景是 500 QPS 持续 20 秒，总请求 10,001 条；不等同于“1 秒内 10,000 次瞬时突发”。
